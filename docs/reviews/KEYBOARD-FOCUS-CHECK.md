## 發現並修正的問題

| 問題                                                                                                                                                                                                               | 修正                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 焦點外框被裁切。Bottom Nav 連結的外框超出畫面邊緣（下、左、右）；rail 與完整 Sidebar 的第一個（或捲動到邊界的）連結外框被 `overflow-y-auto` 容器裁掉上緣或下緣；Quick Add 第一個項目的外框被清單的捲動容器裁掉上緣 | 這四組連結加上 `focus-visible:-outline-offset-2`，把 2px 外框改畫在元素內側。全域 `:focus-visible` 規則（2px solid `--ring`）不變 |

## 1. 瀏覽器實測

**環境**：

- Google Chrome 155.0.8059.39（headless），以 DevTools Protocol 送出真實鍵盤事件（Tab、Shift+Tab、Enter、Esc）。
- 腳本只放在本機暫存目錄，不屬於 repo，也沒有新增套件。
- 尺寸：375×812、768×1024、1440×900。
- 路徑：`/finance/receipts/new`（placeholder 頁）、`/finance`（含主內容連結的帳務 Hub）。
- 執行時間：2026-10-07。

**執行對象**：

1. 修正前：`http://127.0.0.1:3001`（`next dev`）。
2. 修正後：同一個 3001 dev server（會自動套用修改）。
3. 修正後再以 production build（`next build` + `next start`）複驗。

dev 模式會多出 Next.js dev 指示器（`nextjs-portal`）這個 Tab 停點，它不屬於本專案介面，所以不列入判定；production 複驗中沒有出現。

每個尺寸、每條路徑都以鍵盤 Tab 到可見的「新增」按鈕，按 Enter 開啟後檢查：

| 檢查                                                 | 結果（6 組）                                                                               |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 開啟後焦點在 sheet 內                                | PASS。第一個焦點是「關閉」按鈕。這是 Radix Dialog 的預設行為：自動聚焦時優先選擇非連結元素 |
| 連按 Tab 12 次、Shift+Tab 12 次，焦點都留在 sheet 內 | PASS（24 / 24 次都沒有離開），在 9 個停點（8 個項目加關閉鈕）之間循環                      |
| Esc 關閉 sheet                                       | PASS                                                                                       |

### 焦點外框

| 檢查                                | 修正前                      | 修正後（dev 與 production） |
| ----------------------------------- | --------------------------- | --------------------------- |
| 每個停點都是 `:focus-visible`       | PASS                        | PASS                        |
| 外框為 2px solid                    | PASS                        | PASS                        |
| 外框與背景對比 ≥ 3:1（WCAG 1.4.11） | PASS（最低 5.94:1）         | PASS（最低 5.8:1）          |
| 外框沒有被畫面邊緣或捲動容器裁切    | **FAIL**（17 個停點被裁切） | PASS（0 個）                |

**對比計算方式**：外框色（`--ring`）對比其後方最近的不透明背景。

修正前後的截圖都已目視確認：修正前 Bottom Nav「帳務」的外框下緣超出畫面；修正後 Bottom Nav 與 Sidebar 的外框都完整可見。

### 未執行（需要人工或實機）

- 實體鍵盤在實際使用者環境中的操作與主觀清晰度判斷。以上只用自動化鍵盤事件與量測，加上截圖目視。
- 螢幕閱讀器（NVDA、VoiceOver）。
- Windows 高對比模式與 `forced-colors`。
- Firefox、Safari，以及 iOS／Android 外接鍵盤。
- 淺色主題：headless Chrome 以深色主題呈現，淺色模式下的外框對比沒有在瀏覽器量測。

### 觀察（未修改）

1. **沒有「跳到主要內容」連結。** 在 1440 寬時，要先經過 21 個 Sidebar 停點才到主內容。這屬於新增功能，不在本段範圍，留給後續決定。
2. **開啟 Quick Add 後第一個焦點是「關閉」按鈕**，不是第一個項目。這是 Radix 的設計，可以避免按 Enter 時誤導頁；本段沒有變更。

- 不套用 CSS，不能驗證實際外框是否被裁切或對比是否足夠，只能檢查實作所用的 class。實際效果以上面的瀏覽器實測為準。
